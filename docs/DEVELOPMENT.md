# 开发与验证

## 环境与命令

需要 Node.js 22+、npm 和微信开发者工具；可选自己的小程序 AppID 与 CloudBase 测试环境。导入仓库根目录，项目配置已指定前端与云函数目录。

```bash
npm ci
npm run verify
npm run preview:routes
```

`check` 遍历 `scripts/public-files.js` 中定义的公开文件，检查 JS 语法、普通 JSON、默认 AppID/云配置和有限的凭证特征；若已创建 Git 仓库，还检查已跟踪的私有文件。它不证明所有个人信息都不存在，也不审查图片文字。增加顶层目录时同步更新公开文件列表。

## 自动测试

| 测试文件 | 范围 |
| --- | --- |
| airport-data | 机场数量、字段、坐标、唯一 ID、本地表体积 |
| airport | 代码、城市、名称、中文别名搜索与排序 |
| route | 距离、大圆采样、方向与日期变更线 |
| route-animation | 原生路径、兼容回退、视觉速度与拆线 |
| map-dedupe | 同向/往返几何复用，保留记录统计 |
| travel-summary | 清单去重与地区展示名称 |
| flight.service | 本地 CRUD、排序、年份与统计 |
| demo | 单次写入、跨年、已有记录保护与云模式拒绝 |
| cloud-flight | SDK mock 下的服务端身份、跨用户隔离、快照与异常 |
| config | 页面配置与定位权限等回归项 |

测试文件在独立进程中运行，隔离 `wx`、`Page` mock 和模块缓存。无第三方测试依赖；这些测试不等于覆盖率声明，也不替代平台端集成测试。

## 开发者工具验收

1. 空记录时在“我的”导入示例，确认 8 次飞行、8 个机场、7 个国家/地区。
2. 地图检查 PEK–HND 往返共享曲线、方向分开；HND–LAX 在日期变更线处拆线。
3. 记录页切换年份：2025 年 3 条，2026 年 5 条；全部为 8 条。
4. 搜索 `PEK`、`RJTT`、`Tokyo`、`北京`；新增记录后查看地图与统计刷新。
5. 编辑日期/机场，查看距离与年份变化；删除单条后查看总数。
6. 切换页面、隐藏再打开小程序，观察动画停止、恢复与重复循环。
7. 在清空弹窗取消一次确认数据保留，再仅用示例数据测试两次确认清空。
8. 有记录时不显示示例入口；调试直接调用导入也应拒绝覆盖。

本次整理使用微信开发者工具内置的 Node.js 22.16.0 与临时 npm 10.9.4 执行 `npm ci` 和 `npm run verify`，10 个测试文件通过。当前终端的 PATH 尚无独立 Node/npm，日常开发请先安装 Node.js。未执行原生组件/真机验收。真实云端验收见 [部署说明](CLOUDBASE.md)。本地缓存被清理后不可恢复。

## 更新数据与示意图

`npm run sync:airports` 下载并更新三个机场生成文件；支持传入离线 CSV，见 [数据说明](CLOUDBASE.md)。更新后审查数据差异、元数据、数量描述和测试，不在 CI 自动下载变化数据。

`npm run preview:routes` 使用项目的 `buildRouteGeometry()` 和虚构示例生成 SVG，无需网络。改动算法或示例后提交更新图片，CI 检查可重复生成。
